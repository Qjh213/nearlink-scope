# LinkScope · SLE/BLE 链路时延分析工具

> 把"这条链路到底稳不稳"变成可复现的数字。

面向星闪（NearLink / SparkLink）开发者的双端协作式链路测量工具：两块运行探针固件的开发板组成发起端与响应端，量化 SLE/BLE 应用链路的 RTT 分布、抖动、超时、重复和乱序，并比较配置或事务语义变化带来的影响。

“无线示波器”是项目的传播名称，不代表本项目是空口抓包器，也不代表它能在没有对端探针配合的情况下测量任意商用设备。

## 当前状态

**W1 基线已冻结，测量内核复核进行中。** 已完成时基标定、单板自环、SLE 双板 RTT、连接参数扫描和窗口实验，并保存原始日志。主机侧协议/统计自检 32 项与 engine/loopback 集成测试均通过。

当前优先级不是 GUI，而是完成 SLE Write Request/Write Command 对照、使用合理超时重做窗口实验，并核实当前 SDK 中连接参数 `slot` 的实际时间含义。详细计划见 [`docs/接管计划.md`](docs/接管计划.md)。

## 硬件基线

- 2 × BearPi-Pico H3863（Hi3863，Wi-Fi 6 + BLE + SLE 三合一）
- 干扰源：手机热点 / 笔记本 WiFi（脚本化启停）

## 三条设计主线

1. **以 RTT 为主指标** —— RTT 只使用发起端单一时钟；对端处理耗时只使用响应端时钟。跨板时间戳差不解释为单向时延。后续可使用双 GPIO + 同一逻辑分析仪建立单向路径校准。
2. **同板、同事务语义对照** —— 一颗芯片、一根天线、同一套探针协议，并保证 SLE/BLE 使用相同的 Write Request 或 Write Command 语义，避免把 API 事务差异误当成传输层差异。
3. **先测噪声底** —— 用本地回环量出工具自身的调度抖动，报告里注明"仅对超过噪声底的差异下结论"。
