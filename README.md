# LinkScope · SLE/BLE 链路时延分析工具

> 把"这条链路到底稳不稳"变成可复现的数字。

面向星闪（NearLink / SparkLink）开发者的双端协作式链路测量工具：两块运行探针固件的开发板组成发起端与响应端，量化 SLE/BLE 应用链路的 RTT 分布、抖动、超时、重复和乱序，并比较配置或事务语义变化带来的影响。

“无线示波器”是项目的传播名称，不代表本项目是空口抓包器，也不代表它能在没有对端探针配合的情况下测量任意商用设备。

## 硬件基线

- 2 × BearPi-Pico H3863（Hi3863，Wi-Fi 6 + BLE + SLE 三合一）
- 干扰源：手机或笔记本连同一 2.4 GHz AP 持续下载大文件，实测 ≥3 MB/s（≈25 Mbps）才算压满空口；
  手机热点播高清直播（约 2–4 Mbps、占空比约 5%）**不足以构成有效干扰**，见项目日志 P154

## 快速开始

1. 装CH340驱动，并在仓库根目录装好依赖：`python -m pip install -r tools\requirements.txt`。
2. 两块H3863分别烧initiator/responder固件，USB接PC（惯例COM3=发起端，COM4=响应端）。
3. 仓库根目录运行 `python tools\nlscope.py`（或直接双击重建后的 `dist\LinkScope\LinkScope.exe`），主窗口选COM3，工作台新建COM4辅助终端，两端均用115200/8N1/无流控/DTR、RTS关。
4. 点“全部开始”，**先复位COM4再复位COM3**；等COM3打印完整平台签名并出现`measurement-ready`才开始计时。
5. 跑满时长（矩阵默认180 s，稳定性长测≥10分钟）后“全部停止”→“联合导出”。

完整步骤、判读标准与故障排查见 [`docs/上手与复现手册.md`](docs/上手与复现手册.md)；哪些该提交、哪些不该提交见
[`docs/提交与仓库规范.md`](docs/提交与仓库规范.md)。

## 三条设计主线

1. **以 RTT 为主指标** —— RTT 只使用发起端单一时钟；对端处理耗时只使用响应端时钟。跨板时间戳差不解释为单向时延。后续可使用双 GPIO + 同一逻辑分析仪建立单向路径校准。
2. **同板、同事务语义对照** —— 一颗芯片、一根天线、同一套探针协议，并保证 SLE/BLE 使用相同的 Write Request 或 Write Command 语义，避免把 API 事务差异误当成传输层差异。
3. **先测噪声底** —— 用本地回环量出工具自身的调度抖动，报告里注明"仅对超过噪声底的差异下结论"。

`E:\Starklink\文章\link\M1` 至 `M6`。
