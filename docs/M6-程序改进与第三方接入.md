# M6 · 程序改进与第三方测试代码接入

更新时间：2026-11-15

## 1. 问题与结论

当其他人使用 LinkScope 测试自己的链路时，可以继续使用本项目固件，也可以使用自己的测试代码，但两种模式的
能力不同：

- 使用本项目 initiator/responder 固件：当前程序可以直接完成平台签名校验、RTT、超时、重复、乱序、坏包、
  序号缺口和报告导出。
- 使用第三方自己的代码：辅助窗口和分析端原始终端仍可显示、保存任意串口字节；主分析窗口只有在第三方代码
  提供 LinkScope 所需的测量字段后，才能计算链路稳定性。
- 第三方代码只打印普通业务日志时，程序不能从日志外观推导真实 RTT、丢包率或链路稳定性。PC 侧串口到达时间
  还混入板端日志缓冲、UART、USB、驱动和操作系统调度，不能替代空口事务时间戳。

因此，当前程序不是“对任意测试代码零改动即用”的通用分析器。M6 要提供明确的第三方接入契约和适配机制，
而不是放宽解析器、把任意数字行误当成有效样本。

## 1.1 当前实现的具体耦合

当前通用性问题有两层，必须同时解决：

1. **测试代码为分析程序定制**：本项目固件直接输出`S,...`、`# SUM`和固定平台签名，PC解析器只认识这套
   测量事件。换成第三方普通业务代码后，原始日志仍可见，但正式统计所需信息通常不存在。
2. **分析程序为M5实验定制**：`tools/nlscope.py`把cfg500/511/512/513/521/522/523/531/532/541硬编码在
   `M5_PROFILES`，界面的“预期实验”直接读取该字典；启动门再按这些固定字段拒绝不匹配样本。这能保护M5证据，
   但把一次阶段实验的配置写进了通用工具核心。

现有“不校验预期实验”只能关闭profile比对，不能凭空补出第三方代码缺失的序号、时间戳和计数器，因此它不是
通用模式，也不能作为解决方案。

## 2. 第三方代码的最低测量契约

要测量主动请求/响应链路，第三方 initiator 至少需要输出：

```text
S,seq,t1_us,t4_us,rtt_us,bproc_us,dlt_us
```

最低语义要求：

1. `seq`：每次事务唯一且单调递增，用于识别缺口、重复和乱序。
2. `t1_us`：initiator 发出请求时的板端时间戳。
3. `t4_us`：同一 initiator 收到对应响应时的板端时间戳。
4. `rtt_us=(t4_us-t1_us) mod 2^32`：只使用同一块板、同一时钟，作为主 RTT 指标。
5. `bproc_us=t3_us-t2_us`：可选但推荐，来自 responder 同一时钟，用于区分对端处理与链路等待。
6. `dlt_us`：跨板时钟字段，只允许看趋势，不允许解释为精确单程时延。
7. 必须维护 sent/recv/timeout/duplicate/bad/drop 等计数；没有发送总数就不能计算可靠性。
8. 启动时输出角色、链路类型、配置编号、载荷、速率、窗口、超时、自检和 ready 平台签名。

第三方可以不使用本项目的业务逻辑，但必须在其收发路径中加入以上探针。时间戳要尽量靠近真实发送和接收回调，
不能只在打印日志时取时间。

## 3. M6 拟支持的三种接入模式

### A. LinkScope 原生模式

使用本项目固件和现有 `S,...`/`# SUM` 协议。维持严格校验，是正式实验的默认模式。

### B. 第三方兼容输出模式

第三方代码按公开文本协议输出平台签名和样本行。程序不要求其采用本项目内部代码，只要求字段语义与不变量成立。
仓库需要提供最小 C 接入示例、字段说明和自检样例。

### C. 适配器模式

第三方已有固定日志格式时，通过独立适配器把原始行转换成统一 `Sample`/计数器/平台签名事件。适配器不得修改
原始日志；导出时必须同时保存原始行、适配器名称和版本。未经适配器确认的普通日志只能查看，不能进入正式统计。

不提供“仅按 PC 收到串口行的时间估算空口 RTT”的正式模式。它最多可作为日志到达间隔观察，必须明确标注包含
UART/USB/OS 抖动，不能宣传为链路稳定性。

## 3.1 “预期实验”的改造方向

保留“预期实验”这一安全机制，但把它从M5硬编码下拉框改成通用的“实验规格”：

- **自动识别**：从板卡平台签名生成只读规格，用户确认后开始采集；
- **自定义规格**：界面填写role/link/cfg/payload/rate/window/timeout及必选/可选字段；
- **导入规格**：读取JSON文件，便于团队共享和复现实验；
- **历史模板**：M5配置作为普通内置模板保留，不再成为程序核心常量；
- **仅原始日志**：明确不进入稳定性统计，而不是含糊地叫“不校验”。

实验规格只描述“本轮预期什么”，协议适配器负责“怎样从日志得到测量事件”，统计引擎负责“怎样计算指标”。
三者必须分离，避免以后每增加一种板卡代码或实验都修改GUI和核心解析器。

## 4. M6 程序改进清单

1. 实验向导：串口、角色、复位顺序、预期配置、目标时长和输出目录一次配置。
2. 自定义实验配置：允许用户声明 cfg、payload、rate、window、timeout 等期望值，不再只限内置 M5 profile。
3. 协议/适配器接口：原生 LinkScope、第三方兼容文本协议、显式安装的日志适配器。
4. 接入自检：开始正式采样前验证签名、字段范围、RTT 恒等式、序号行为和计数器完整性。
5. 能力分级：界面明确显示“仅原始日志 / 可算间隔 / 可算 RTT / 可算可靠性”，避免超出证据下结论。
6. 自动证据校验：检查导出文件、样本数量、序号、签名、异常行和固件/适配器身份。
7. 会话类型兼容：正确区分 active sample 与 monitor report，兼容历史 `responder_COM4.log` 文件名。
8. 长时间稳定性：至少两小时运行，检查内存、文件句柄、UI响应、串口重连和持续落盘。
9. 一键复现与报告：把实验条件、版本、哈希、统计口径和限制自动写入报告。
10. 干净 Windows 验收：无 Python 环境完成安装、识别串口、开始/停止、导出和卸载。
11. 移除GUI对`M5_PROFILES`的直接依赖；M5模板迁移到可加载的实验规格数据。
12. 将“协议适配器、实验规格、统计能力”分别建模并写入`run.json`，报告能说明本轮为何有资格计算某项指标。

## 5. 验收边界

第三方代码接入只有同时满足以下条件，程序才可显示“可测链路稳定性”：

- 样本可以唯一关联一次发送与对应接收；
- RTT 的起止时间戳来自同一时钟；
- 有明确超时阈值与发送总数；
- 能识别重复、乱序和坏包；
- 平台签名或自定义实验元数据完整；
- 原始日志不被适配器覆盖或改写；
- 导出报告标明代码/固件或适配器版本。

若缺少其中任一关键条件，程序必须降级为原始日志查看器或有限指标模式，不能给出完整稳定性结论。
