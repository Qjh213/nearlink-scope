# 探针协议（LinkScope Probe Protocol v0.1）

> 实现依据。所有字段小端序。

## 设计约束

- 单帧必须小：默认 `SLE_UART_SERVER_SEND_BUFF_MAX_LEN = 40`，性能模式下 250B。
- 不允许变长编码（解析开销会污染时间戳）。
- 时间戳在收发回调第一行取，早于任何 memcpy / 分支 / 日志。

## REQ（A → B，发起端 → 响应端）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `magic` | 0xA5，快速丢弃杂包 |
| 1 | 1 | `type` | 0x01 = REQ |
| 2 | 2 | `seq` | u16 自增，回绕；用于丢包/乱序/重复 |
| 4 | 4 | `t1_us` | A 端发出时刻，u32 微秒 |
| 8 | 4 | `cfg_id` | 当前实验配置编号，便于事后归因 |
| 12 | n | `fill` | 填充字节，把包长拉到 8 / 64 / 250B 档位 |

## RSP（B → A，原样回显 + 打点）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `magic` | 0xA5 |
| 1 | 1 | `type` | 0x02 = RSP |
| 2 | 2 | `seq` | 原样回显 |
| 4 | 4 | `t1_us` | 原样回显 |
| 8 | 4 | `t2_us` | B 收到 REQ 的时刻 |
| 12 | 4 | `t3_us` | B 发出 RSP 的时刻 |
| 16 | 4 | `cfg_id` | 原样回显 |

RSP 固定 20B。

## 时间分解

```
RTT = t4 - t1                        ← 只用 A 的时钟，主指标，无同步问题
    ≈ (t2-t1) 上行 + δ               ← 半程估计（含 B 时钟偏差 δ），不做结论
    + (t3-t2) B 处理时延             ← B 的时钟内，精确可得
    + (t4-t3) 回程 - δ               ← 跨时钟，含未知 δ，只能看趋势/抖动
```

> 更正（W1）：`t4-t3` 跨了 A/B 两个时钟，不是"同一时钟精确可得"，绝对值无意义。
> 能直接下结论的只有 `t4-t1`（RTT 本身）和 `t3-t2`（对端处理）。
> A 侧"从收到数据到打完时间戳"的开销要靠 hello_timing / 本地回环单独测，不能从 `t4-t3` 里读。

`t4` 由 A 端在收到 RSP 的第一行取。

## 回绕处理

u32 微秒约 71.6 分钟回绕一次。计算时用无符号减法：

```c
uint32_t rtt = (uint32_t)(t4 - t1);
```

跨回绕天然正确。

## 对端（B）实现铁律

收到 REQ 后只做三件事：读时间戳 → 填 RSP → 立即回发。不打印、不转发 UART、不做条件分支以外的任何工作。

## 统计口径

| 指标 | 定义 |
|---|---|
| 丢包率 | `1 - 收到RSP数 / 发出REQ数`（超时阈值默认 50 ms） |
| 乱序 `ooo` | RSP 的 `seq` 相对“最近前向最大序号”的回退次数（`int16` 差分为负）；u16 回绕不算乱序 |
| 重复 `dup` | 同一 `seq` 出现多次 |
| 分位数 | 对数分桶直方图插值（每倍频程 8 桶，1us–200ms，约 141 桶），板端近似、约 6% 误差 |
| 抖动 | 相邻样本 RTT 差分的平均绝对偏差 |

## v0.2 变更（M6 第一批，2026-11-15）

1. **REQ 填充字节带 seq 特征**：`fill[i] = (uint8_t)i + (uint8_t)(seq & 0xFF)`（`i` 为帧内偏移）。
   响应端解析时逐字节校验，不符返回 `PROBE_ERR_PAYLOAD = -5` 并计入 `bad`。
   这是**空口格式变化**：新旧固件混跑时，旧 initiator 发的全零填充会被新 responder 判坏帧。
2. **RSP 回显 `cfg_id`，由 A 校验**：B 端不强制自己的编译期 cfg 等于 A；A 发现 `rsp.cfg_id != 自己的 cfg_id`
   直接计 `bad_frame`。跨配置混跑不再“静默通过”。
3. **`# SUM` 新增字段**：`ooo`、`rx_drop`（UART 接收侧丢弃）、`send_err`、`cfm_err`（链路层写确认失败）、
   `dlt_neg`（`t4-t3` 为负而被归零的样本数）。`drop` 仍只表示 ring buffer 丢弃。
4. **响应端队列**：深度 5 → 16；队满改为计 `qdrop`（不再混入 `bad`）；断链后旧 RSP 用 epoch 标记丢弃并计 `stale`。
5. **PC 端与板端分位数口径不同**：PC 端改为线性插值（`numpy.percentile` 口径），板端仍是直方图近似；
   同一份数据两端 p99 可能差 1–3%，跨端比较必须以 PC 端为准。

## v0.3 变更（M6 第二批，2026-11-15）

1. **CSV schema 去掉 `dlt_us`**：导出表头现为 `seq,t1_us,t4_us,rtt_us,bproc_us,wall_time`。
   `t4-t3` 跨两个设备时钟、含未知偏差 δ，既不能当单向时延、也不能用 `rtt` 去约束它
   （断链重连后 δ 换方向，旧校验 `dlt_us <= rtt_us` 曾把 65% 的有效样本判成坏行）。
2. **`dlt` 降级为诊断字段**：`Sample.dlt_us` 仍解析、仍进内存（`None` = 该数据没有该字段，`0` = 板端确实报 0），
   但不再写进 CSV；`# SUM` 的 `dlt_neg` 只表示“负值被归零的样本数”，不可读成“下行时延”。
3. **旧文件兼容**：`load_csv()` 对带 `dlt_us` 列的旧 CSV 仍能加载（该列被读入内存但不参与校验），
   M5/M6 历史证据无需转换即可回放。
4. **不变式只剩同钟两条**：`rtt_us == ((t4_us - t1_us) & 0xFFFFFFFF)` 与 `bproc_us <= rtt_us`；
   跨时钟量一律不设上界。
