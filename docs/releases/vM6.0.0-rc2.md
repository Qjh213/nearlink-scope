# NearLink LinkScope M6.0.0-rc2

M6 的目标不是加功能，是把"我信"变成"谁都能验"：五个计数器真正上报、缺失值不再伪装成 0、
导出带自检并拒绝覆盖、原始字节另存、支持一键复现与第三方数据接入。

本版相对 `M6.0.0-rc1` 只有一处改动：**固件继承判定**。原规则按"选择时间早于会话开始"判断，
而"先选固件、再开始采集"恰是正常操作顺序，导致每轮导出都报一条 `firmware=warn`。改为按
"这次选择是否已被上一次导出消费过"判断，同一路径重新选中即视为重新确认。

## 这个版本里有什么

- **计数器不再"假零"**：板端 SUM 从 16 字段扩到 24 字段，新增 `ooo`、`rx_drop`、`send_err`、
  `cfm_err`、`dlt_neg`；未收到 SUM 时 PC 端显示 `—` 而不是 0。
- **证据不会静默消失**：导出拒绝覆盖（`open("x")`），每条串口旁路保存 `.raw` 原始字节，
  恢复目录不可写时降级而不是挡住采集，显示窗口限制 5000 行。
- **口径写进文档**：分位数改线性插值；板端直方图约 6% 分桶误差写明；`dlt` 因跨时钟被删除
  （CSV v0.3，旧文件仍可回放）。
- **能力与复现**：会话自动声明"能算什么"（raw/interval/rtt/reliability）；`--reproduce` 把记录值与
  重放值逐项对照；实验向导按八步给结论；第三方 CSV 用 JSON 适配器接入。
- **固件**：REQ 填充模式逐字节校验、RSP 回显 `cfg_id` 由发起端核对、responder 队列 16 深且
  队满/断链分别计 `qdrop`/`stale` 并带 epoch。

## 已知限制

- **未在干净机（无 Python 的 Windows）上装过**：按用户决定跳过该项验改，此处如实标注。
- `qdrop`/`stale` 两个计数器**尚未实测到非零**（需要"断链但保持供电"的 RF 屏蔽条件）。
- 应用层 CRC 决定不做；协议停在 v0.3。
- 超过 4 小时的连续采集未验证：内存斜率约 1.3 MB/min，8 小时外推约 750 MB。
- 40 Hz 下 `seq` 27.3 分钟回绕一次，回绕计入 `pc_sequence.wraps`，不是丢包。
