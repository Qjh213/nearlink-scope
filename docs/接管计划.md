# LinkScope 接管计划

更新日期：2026-11-09

## 1. 当前定位

LinkScope 是一套需要双端探针固件配合的 SLE/BLE 应用链路测量与配置对比工具。它不是空口抓包器，不把当前开发板的实测数字外推为星闪协议或芯片的通用性能。

## 3. 已确认的当前 SDK 能力

当前 SDK 头文件提供：

- `ssapc_write_req()`：写请求，结果由 write confirmation 回调返回；
- `ssapc_write_cmd()`：无响应写命令；
- `SSAP_OPERATE_INDICATION_BIT_WRITE_NO_RSP`：Server 属性允许无响应写入；
- `sle_connection_param_update_evt_t`：回调返回最终 interval/latency/supervision 原始值。

连接参数头文件只把 interval 标为 `slot`，没有在该结构定义处声明每个 slot 的绝对时间。项目当前使用的 125 µs 换算必须保留 SDK 版本与实测证据，不能写成所有 WS63 SDK 的通用规格。

## 4. M1：测量内核复核

### 4.1 SLE 写语义 A/B

同一固件通过 Kconfig 选择：

```text
Write Request → Notification
Write Command → Notification
```

保持连接参数、Payload、频率、窗口、超时和任务优先级一致。

验收：

- 两种模式均完成至少 3 分钟稳定运行；
- 输出唯一完成速率、RTT 分位数、超时、重复、乱序；
- Request 模式另外输出 write confirmation 分布；
- 结论只描述当前平台签名。

### 4.2 窗口实验重做

```text
window = 1 / 2 / 4 / 8
timeout = 500 ms
duration >= 120 s / 档
```

验收指标以单位时间完成的唯一序号数为主，提交数只作为辅助指标。

### 4.3 插桩扰动 A/B

- full：记录 t1/t2/t3/t4 和所有诊断字段；
- minimal：只记录必要序号与 RTT。

验收：比较两种模式的 p50/p99 和完成吞吐率，说明测量逻辑是否显著扰动被测路径。

## 5. M2：BLE 公平对照

BLE 与 SLE 分别测试 Write Request 和 Write Command。只有事务语义相同的两组才能作为主对照。

BLE 广播、扫描、连接、MTU、特征发现、CCCD、写入和 Notification 必须逐阶段留验收日志。

## 6. M3：PC 工具

第一版只实现：

- 串口实时数据源；
- 历史日志回放；
- RTT 时间序列；
- 直方图与 CDF；
- p50/p90/p99/p99.9/max；
- 超时、重复、乱序统计；
- 原始数据和 Markdown 报告导出；
- 平台签名常驻显示。

## 7. M4：发布验证

- 两小时稳定性测试；
- 至少两个距离档位；
- 安静与 2.4 GHz 干扰环境；
- 原始数据、配置、固件哈希和分析命令齐全；
- 误差预算、已知限制和移植文档齐全。
