# 提交与仓库规范

一句话原则：**仓库放"能重建结果的东西"，不放"结果本身"。**

代码、文档、脚本、清单、SHA 记录 → 入库。
实验日志、固件二进制、构建产物 → 不入库，留在本地证据目录，靠命名和 SHA 自证。

---

## 1. 三类内容怎么处理

| 内容 | 例子 | 处理 |
|---|---|---|
| 源码与测试 | `tools/*.py`、`serial_reader.py`、`tests/`、`firmware/linkscope/*.c` | **入库** |
| 脚本与配置模板 | `firmware/scripts/*.ps1`、`tools/requirements.txt` | **入库** |
| 文档 | `docs/*.md`、`README.md`、`tools/README.md` | **入库** |
| 计划与清单 | `artifacts/logs/M5/manifest.csv`、`artifacts/firmware/SHA256SUMS.txt` | **入库** |
| 单轮实验日志 | `artifacts/logs/M5/cfg*/`、`initiator_COM3.csv` | **不入库**（`.gitignore`） |
| 固件包 | `*.fwpkg` | **不入库**（已忽略；早先跟踪的几包保留，不再新增） |
| 构建产物 | `dist/`、`out/`、`build/` | **不入库**（已忽略） |
| 临时文件 | `*.bak.*`、`_tmp*`、`out/_tmp_tests/` | **不入库** |

为什么要分：一轮日志动辄几 MB 到几十 MB，进 git 后每次 clone 都背着；而且日志可以重跑，代码不能重写。需要复核时用 SHA-256 + README 定位到具体那一包固件。


这两份是知识材料（QCOM 行为规格 371 行 + 给实现方的交接包 120 行），不是实验日志，值得入库。

### 明确不要提交的

```text

*.fwpkg                     固件包
out/ dist/ build/           构建产物
docs/*.bak.*                编辑备份
```

做完 A/B/C 后，`git status` 里应当只剩被忽略项，看不到 `artifacts/logs/M5/` 的一堆文件。若还看得到，说明 `.gitignore` 还没补（见第 4 节）。

## 3. 每次提交前检查清单

- [ ] `python -m unittest discover -s tests` 全绿（13 项）
- [ ] `python tools\test_nlscope.py` 全绿（31 项）
- [ ] 没有新的 `readline()` / `for line in ser` / 按 `\n` 分行
- [ ] 接收路径没有加内容过滤
- [ ] 没有把实验日志、固件包、`out/` 加进暂存区
- [ ] 文档里的数字与 `run.json` 对得上（时长、样本数、分位数）
- [ ] 改了固件就更新 `artifacts/firmware/SHA256SUMS.txt` 与本轮 README

```powershell
git status --short          # 看有没有误加
git diff --cached --stat    # 提交前看一眼范围
```

```gitignore
# 实验证据：单轮日志与导出不入库（仓库只保留 manifest.csv 与矩阵进度表）
```

效果：`git status` 从 94 项降到 14 项，只剩待提交的代码/文档，以及 `逆向QCOM/` 这两份知识文档。

两个必须知道的细节：

- `artifacts/logs/M5/` 下**已有部分文件被跟踪**（cfg500/511/512/513 的少数 README、csv、json）。忽略规则不会让它们消失，也不会把它们移出仓库；只是新文件不再进来。
- 被忽略的文件没有丢失，仍在本地磁盘。需要复核时可 `git add -f <路径>` 强制入库，但请先想清楚这是不是"结果本身"。

## 5. 提交信息格式

`<领域>: <做了什么>`，一句话说清动机，必要时第二行写原因。

```text
firmware: 队列读失败路径让出CPU，修复P139回调NMI崩溃
tools: 按QCOM行为规格重写串口接收（CR分行/空闲flush/可观测丢弃）
docs: 登记cfg521长测结果并补充上手手册与提交规范
```

一次提交只做一件事；固件修复不要和 PC 改造混在一起，否则回滚时无法只退一半。

## 6. 实验证据怎么留

- 位置：本地 `artifacts/logs/M5/cfgNNN_<描述>/runX/`，不入库。
- 一轮六件套 + `README.md`，命名 `<MMDD>_cfg<NNN>_run<N>_<pass|fail>`。
- README 必填两端固件 SHA-256、PC 版本、距离/遮挡/朝向、起止时间、时长、有效样本数、结论。
- 定期把整个 `artifacts/logs/M5/` 打包到仓库外的归档盘；仓库里只保留 `manifest.csv` 和矩阵 §8 的进度表。
- 固件包放 `artifacts/firmware/`（不入库），在 `SHA256SUMS.txt` 里登记一行：`<sha256>  <文件名>`。

这样别人拿到仓库 + 归档盘，就能用"清单 → SHA → 日志目录"这条链复核任何一轮，而不需要把几十 MB 日志塞进 git。
