# 星闪（SLE）协议问题集

> 用法：先自己答，再查规范/SDK 核对，最后用本项目的数据或补一轮实验验证。
> 标 **★** 基础（读完概述就能答）、**★★** 进阶（要翻规范或 SDK）、**★★★** 深水（要读实现或设计实验）。
> 每题后面的“项目锚点”指本项目里能验证它的地方，不是答案。

## A. 定位与体系（SLE 是什么、不是什么）

- **Q1 ★** 星闪（NearLink）包含哪几种接入方式？SLE 与 SLB 各自面向什么场景？我们这套用的是哪一种？
- **Q2 ★** SLE 与 BLE 在“连接建立、连接事件、ARQ、GATT 式属性”这些概念上，哪些同构、哪些不同？
- **Q3 ★★** SLE 在协议栈里分了哪几层？各层职责边界在哪？我们代码里 `link_sle_initiator.c` 调用的 API 属于哪一层？
- **Q4 ★★** SLE 的寻址方式是什么（设备地址、连接 ID、句柄）？一个 responder 能被几个 initiator 同时连接？
- **Q5 ★★★** SLE 的“服务发现/属性”模型与 BLE GATT 的差异在哪？为什么我们的样例可以直接用自定义帧而不走属性读写？

## 建议的三轮学习法

1. **第一轮（不带资料）**：只看题目，把能答的写下来，答不出的标 `?`。目标是暴露盲区，不是答对。
2. **第二轮（查规范/SDK）**：按 A→K 顺序补，重点把 **Q13–Q18（写语义）**、**Q26–Q30（时间语义）**、**Q51–Q57（实现）** 答完整——这三组直接决定你能不能解释自己测出来的数。
3. **第三轮（做实验）**：从 K 组挑 3 个，设计最小实验（每轮 ≤10 分钟），用现有工具链采集、导出、`--reproduce` 复现，把结论写回问题下面。
